OSS PROJECT INTRO · OLLAMA 系列第 2 期：5 分钟跑起来

5 分钟跑起来 Ollama：本地装好它，亲手跑通第一个模型

上一期我们认识了 Ollama：一行命令就能在自己电脑上跑开源大模型的运行器，也划清了它与云端 API 的选型边界。今天动手验证。五分钟后你将亲手做出五样东西：装好的 Ollama、拉到本地的模型、两轮上下文连贯的对话、看得见的运行状态，以及一条命令收拾干净。全程不写代码，命令逐字对照官方 README 与 docs.ollama.com（基准 Ollama v0.34.2，2026-09-15 发布，2026-09-19 核对）。

🦙 本地大模型运行器 · Go · MIT 📦 基于 v0.34.2（GitHub Latest，2026-09-15 发布） 📅 2026-09-19 · 第 2 期 ⏱ 预计阅读 12 分钟

01动手前的三个共识

上一期立住了三件事，本期全部要用上。其一，Ollama 是什么：一个开源的本地大模型运行器，把"下载模型权重、启动推理服务、暴露对话接口"三件事打包成一条命令。其二，它解决什么：想试用一个模型，不用租 GPU、不用配环境、不用注册账号，成本压到一条命令。其三，选型边界：数据敏感、要离线、调用量大，选本地；能力优先、不想管硬件，选云端。本期结束时，这条边界会从"概念"变成你亲手验证过的事实。

本期五步演示链一气呵成：安装 → pull 拉模型 → run 连聊两轮 → ls / ps 看状态 → stop / rm 清理收尾。每一步的命令都能在官方文档里逐字对上，出任何问题先回文档。

02环境清点：门槛比你想的低

  • 系统：Windows 10 22H2 及以上（Home/Pro 均可）、macOS Sonoma 14 及以上、Linux 一行脚本（官方 docs 各平台页口径）；
  • 磁盘：官方 Windows 页要求安装留足 4GB 空间，模型文件按需另算——本期主角 qwen3:4b 只要再加 2.5GB；
  • 硬件：NVIDIA 与 AMD Radeon 显卡自动 GPU 加速；没有独显，纯 CPU 跑小模型照样流畅；
  • 三不需要：不需要 Python、不需要 Docker、不需要 API Key——不注册、不登录也能跑本地模型。

来源：ollama.com/download（2026-09-19 截图）。官网下载页为 macOS / Linux / Windows 三个页签：Windows 页签给出一行 PowerShell 命令 irm https://ollama.com/install.ps1 | iex，或按钮下载 OllamaSetup.exe，页脚注 Requires Windows 10 or later。

版本钉子：本系列口径锚定 Ollama v0.34.2——GitHub Latest（github.com/ollama/ollama），2026-09-15 发布。Ollama 发版很勤，你看到这期时可能有更新版本，命令骨架不变，以官方文档当前页为准。

03第一步：一条命令装好它

官方 README「Download」段给三大系统各一行命令，Windows 用 PowerShell，macOS 与 Linux 用同一条 curl 脚本：

$ irm https://ollama.com/install.ps1 | iex        # Windows（PowerShell）
$ curl -fsSL https://ollama.com/install.sh | sh   # macOS / Linux

安装器不需要管理员权限，装进你的用户目录；Windows 版装完 Ollama 在后台常驻，ollama 命令直接进 cmd 与 PowerShell。怎么确认成功？新开一个终端（旧终端拿不到新写入的 PATH），敲：

$ ollama -v

回显版本号即安装成功（ollama -v 出自官方 docs 的 Linux 手动安装页，用于验证服务在跑）。至此第一步完成，全程不到两分钟。

来源：github.com/ollama/ollama README「Download」段（v0.34.2，2026-09-19 核对）。macOS 也可下载 Ollama.dmg 拖进 Applications；安装方式随版本可能更新，以官方 README 当前页为准。

04第二步：把模型拉回家——名字、冒号、标签

动手前先学会给模型起名。模型库（ollama.com/library）里的完整型号是「名字:标签」：模型名 qwen3，冒号后是标签。以通义千问 Qwen3 为例（模型库页 2026-09-19 口径）：qwen3:4b 下载体积 2.5GB、4B 参数、256K 上下文；qwen3:8b 挂 latest 是默认标签，5.2GB；往下还有 0.6b（523MB）、1.7b（1.4GB），往上 14b、32b 一路到 235b。标签越大数据越大、能力越强，选够用的就好，本期选 4b 这一档。

$ ollama pull qwen3:4b
pulling manifest
pulling 359d7dd4bcda... 100% ▕████████████████▏ 2.5 GB
success

回显为本地运行行为示例：先对清单，再出进度条，最后一句 success。中途断网、关机都不怕——重跑同一条 pull 会从断点续传，不必推倒重来。模型落在本地磁盘，从此它就是你电脑上的一个普通文件。

来源：ollama.com/library/qwen3/tags（2026-09-19 截图）：qwen3 全系累计 37.4M 次下载，qwen3:4b 行显示 2.5GB / 256K / Text；ollama pull 模型名:标签 逐字对照官方 docs「CLI Reference · Download a model」（示例模型原文为 gemma4）。

05第三步：run 起来，连聊两轮

$ ollama run qwen3:4b
>>> 用一句话介绍你自己
我是 Qwen3，来自通义千问系列的小型模型，随时帮你答疑解惑。
>>> 把刚才那句话压缩成十个字
四十亿参数的中文小助手。
>>> /bye

两条回答均为本地运行行为示例（qwen3 是思考型模型，回答前会先输出一段思考，官方 docs「Thinking」页口径，示例中省略）。关键在第二轮：让它压缩上一句，它答得出来——同一个会话内上下文是连续的，这就是"真的在对话"而不是一问一答的查询机。聊完敲 /bye 退出（官方 quickstart 原文提示），程序安静下来，模型文件还躺在本地。

06第四步：ls 看家底，ps 看运行

$ ollama ls     # 已下载：名字 · ID · 体积 · 修改时间
$ ollama ps     # 运行中：多出加载位置与驻留时间
NAME       ID            SIZE     MODIFIED
qwen3:4b   359d7dd4bcda  2.5 GB   4 minutes ago
NAME       ID            SIZE     PROCESSOR    UNTIL
qwen3:4b   359d7dd4bcda  2.5 GB   100% GPU     4 minutes from now

两个查看命令各管一摊：ls 列本地已下载的模型；ps 列正在内存里运行的模型。官方 FAQ 原文口径：ps 的 Processor 列显示模型被加载进了哪块内存（GPU 还是 CPU/RAM），UNTIL 是驻留倒计时。为什么刚才 /bye 退出了对话，ps 里还在？模型默认在内存里多驻留几分钟，等你下次调用时免去重新加载——这是官方设计的行为，不是没退干净。

07第五步：stop 卸内存，rm 删文件

$ ollama stop qwen3:4b   # 卸出内存，文件还在
$ ollama rm qwen3:4b     # 连文件一起删，释放 2.5GB
deleted 'qwen3:4b'

两个清理命令分工明确：stop 让模型立即退出内存、释放算力，磁盘上的 2.5GB 还在；rm 才真正删除文件（回显 deleted '模型名'，本地运行行为示例）。本地模型的妙处就在这：删了随时能回，一条 pull 拉回来又是几分钟的事。试错的成本被压到可以忽略。

08跑通之后：这台机器长什么样

回看五步链路会发现：你敲的每条命令只是前台，真正干活的是常驻后台的一个服务进程——它从本地磁盘读模型文件，调度 GPU 或 CPU 推理。官方 FAQ：服务默认只绑定本机回环地址 127.0.0.1 的 11434 端口，外面够不着；设环境变量 OLLAMA_HOST 可改绑定。同一端口还挂着一整套接口：REST 原生接口 /api/chat，以及 OpenAI 兼容层 /v1/chat/completions——聊天窗口其实只是壳，改个地址就能让现成应用接上本地模型。

$ curl http://localhost:11434/api/chat -d '{
  "model": "qwen3:4b",
  "messages": [{"role": "user", "content": "Why is the sky blue?"}],
  "stream": false
}'

命令结构逐字对照官方 README「REST API」段（README 示例模型为 gemma4，此处换成已拉取的 qwen3:4b）。返回是一段 JSON：message.content 装着回答，done 表示生成结束。你的程序调它跟调云端接口写法几乎一样，区别只有两点：地址是本机，账单是零。第 4 期实战篇就接这里。

来源：docs.ollama.com/quickstart（2026-09-19 截图）：官方 Quickstart「Get started」原文 Download Ollama for macOS, Windows, or Linux. Open the app, or get started from your terminal: ollama；Follow the setup prompts. Sign in to use cloud models, or choose a local model.——注意官方现在也提供云模型（登录后调用），本期的 qwen3:4b 是纯本地模型，跑起来全程不联网。

09钩子：断网之后再聊一轮，会怎样？

本地模型照答不误——模型文件和推理都在你这台机器上，机场高铁不掉线；换云端 API，断网即停。把上期的选型边界落到实处：

  • 选本地的三个信号：数据不能出本机（提问与回答都不经网络）、环境要离线、调用量大到按量计费肉疼——代价是参数量小、复杂推理有上限；
  • 选云端的三个信号：能力优先、突发流量大、不想管任何硬件——代价是数据出公网、按调用量付费；
  • 两者不是敌人：Ollama 一套命令既能跑本地模型也能接云模型，本地试、云端产，同一条命令骨架。

10高频翻车速查（按出现概率）

  • ollama: command not found：刚装完当前终端没拿到新 PATH——关掉重开一个终端再试；
  • pull 到一半失败或很慢：重跑同一条 pull 断点续传；2.5GB 按家庭宽带通常几分钟；
  • Windows 终端进度条显示方块乱码：官方 docs Windows 页原文——进度指示用了 Unicode 字符，老终端字体可能显示为方框，换终端字体即可；
  • run 报显存或内存不足：换更小的标签，qwen3:0.6b 只要 523MB（模型库页口径），纯 CPU 也能跑；
  • 端口冲突或想让局域网访问：默认绑定 127.0.0.1 的 11434；设 OLLAMA_HOST 可改绑定（官方 FAQ）——改绑定前先想清楚第 12 节那道题；
  • 照抄网上教程的 ollama run llama3 对不上：示例随版本更新，命令骨架不变、模型名可替换，以 docs.ollama.com 当前页与模型库为准。

11随堂小测

每题点击选项立即反馈 · 共 3 题

1. pull 拉到一半断网了，最省事的做法是？

  • 先卸载 Ollama 重装再拉
  • 重跑同一条 ollama pull，从断点续传
  • 立刻换 qwen3:0.6b 重新拉

2. /bye 退出对话后，ollama ps 里还能看到模型驻留，为什么？

  • 命令没执行完，出了 bug
  • 模型已经删掉了，显示的是缓存
  • 官方设计的驻留等待：等下次调用免加载，stop 可立即卸出

3. 你写好的程序想调用本地模型，正确姿势是？

  • POST http://localhost:11434/api/chat，或走 /v1 兼容接口
  • 只能通过聊天窗口手动复制粘贴
  • 先把模型上传到云端再调用

12思考题（点击展开解析）

思考一：stop 和 rm 都能让 ps 清空，它们的本质差别是什么？为什么 Ollama 把"清理"拆成两个命令？

两个命令操作的是模型生命周期里两个不同的阶段：run 之后，模型经历"磁盘文件 → 加载进内存 → 推理计算"，stop 只做第二段的逆操作（卸出内存、释放算力），文件不动，下次 run 免下载、秒级就绪；rm 直接删掉第一段的文件本体，释放磁盘，下次要重新 pull。拆成两个命令，对应的是两种真实诉求："暂时不用了"和"确定不要了"。高频试用场景里，大多数"不用了"其实是暂时的——今天试 qwen3:4b，明天可能再回来对比 0.6b，如果清理只有"删除"一档，用户就得在"白占 2.5GB 磁盘"和"重新下载几分钟"之间二选一，试错成本立刻回弹。顺带回头看 ps 的 UNTIL 倒计时：驻留机制其实就是系统帮你自动做"软清理"——算力是稀缺的，磁盘是便宜的，所以内存自动卸、磁盘留给用户手动删。三层存储（磁盘、内存、算力）各有各的回收策略，一条命令对应一层，这就是 Ollama 命令面设计的逻辑。

思考二：Ollama 默认只绑 127.0.0.1。什么时候才值得用 OLLAMA_HOST 改成对外绑定？改之前必须想清楚什么？

值得改的场景其实很窄：局域网里多台机器共享一块好显卡是最典型的一个——比如让笔记本调用台式机上的模型，省得每台机器各存一份权重。改之前必须想清楚的第一件事是：这个端口上没有任何鉴权。绑定一改成 0.0.0.0，局域网里任何人都能 POST 一条对话、消耗你的显存、读你的模型——接口本身不带用户体系，等于把你家插座接到了楼道里。所以官方默认值才敢写死 127.0.0.1：最安全的选择往往就是最方便的选择，两者在这里恰好重合。真要对外，正确顺序是：先收窄（绑具体内网 IP 而不是 0.0.0.0）、再叠加网络层防护（防火墙白名单、反代加认证，官方 FAQ 给了 Nginx 与隧道示例）、最后才开放。这个默认值本身就是一次架构表态：本地优先、安全默认，暴露是显式选择而不是隐式后果——第 3 期拆架构时你会看到，这个取向贯穿 Ollama 的整个设计。
