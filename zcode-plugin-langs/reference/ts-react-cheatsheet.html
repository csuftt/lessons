一、TypeScript 核心（本仓库用到的）

写法含义备注
const x: string = 'a'变量类型标注常用 const；let 用于可变
interface Props { path: string }对象类型契约组件 props 的标配；字段用 ? 可空：since?: number
type View = 'chat' | 'history'联合类型（字面量枚举）本仓库 App.tsx 视图切换用
import type { X } from '...'仅类型导入编译后消失，零运行时开销
a ?? b空值合并（null/undefined 时取 b）对应 Kotlin ?:
a?.b可选链访问对应 Kotlin ?.
declare global { interface Window {...} }给运行时注入的全局变量写类型bridge.ts 给 Java 注入的 __ZCODE_CEF_QUERY__ 等声明
<T> 泛型类型参数useStore<StoreState>((set, get) => ...)
function f(p: string): number函数参数/返回值类型没返回写 : void

二、React 核心（组件 = 函数）

概念写法一句话
组件function X({ props }: Props) { return <div/> }一个返回 JSX 的函数
JSX 插值{表达式}花括号里写 JS 表达式
props<X path={p} onRemove={fn} />父传子的"参数表"，只读
事件onClick={fn}、onChange={fn}驼峰命名；回调由父组件传入
条件渲染{cond && <A/>} / {cond ? <A/> : <B/>}JSX 里用 JS 控制
列表渲染{list.map(x => <Item key={x.id} />)}必须给 key
classNameclassName="file-ref"HTML 的 class 的替代

三、Hooks 速查

Hook写法用途 / 注意
useStateconst [v, setV] = useState(0)局部状态。值变了 → 重新渲染。只取 setter 不取值 = 强制刷新技巧
useEffectuseEffect(() => { ...; return cleanup }, [deps])副作用（定时器/订阅）。清理函数必须写；空依赖 [] = 只挂载时执行
useMemoconst x = useMemo(() => calc(), [deps])昂贵计算缓存（本仓库用得少）
useCallbackconst fn = useCallback(() => ..., [deps])函数引用稳定（配合 memo 子组件）
自定义 Hookfunction useTheme() { ... }以 use 开头的函数封装复用逻辑，仓库实例 hooks/useTheme.ts

四、Zustand 状态管理

API写法说明
建 storecreate<T>((set, get) => ({ ... }))状态 + action 一个对象搞定
改状态set({ streaming: true }) / set((s) => ({ ... }))浅合并；函数式写法可基于旧值
读最新get().currentSessionIdaction 内部读当前状态
组件订阅useStore((s) => s.messages)selector 粒度越细，重渲染越少
外部改useStore.setState({ askUser: null })不经过 action 直接改（AskUserDialog 关闭用）

六、术语小词典

术语含义
JSX在 JS 里写类 HTML 标签的语法，React 编译成 JS 调用
props组件参数表（只读，父传子）
state组件/全局可变状态；变了就重渲染
渲染执行组件函数产生新界面的过程
副作用渲染之外的事（定时器/网络/订阅），必须放 useEffect
selector从 store 里选字段的订阅函数 (s) => s.x
actionstore 里改状态的操作函数
乐观更新不等后端确认，先本地把效果画出来（本仓库用户消息立即上屏）
mock开发模式伪造后端响应（bridge.ts 的假 Java）
singlefilevite 把全部资源打进一个 HTML（生产给 JCEF 加载）
HMRdev server 热重载：改代码浏览器即时刷新
codiconVS Code 图标字体（cc-gui 同款，Webview 里当图标用）

七、易错点（本仓库踩过的）

  • 组件必须 import './xxx.less' 才会被 vite 打进包——忘 import 样式不生效
  • 高频流式事件不要每个都 set——用 onStreamBatch 一次处理整批
  • JCEF 里 console.log 看不到——用 bridge.ts 的诊断面板（onDiagLog）
  • StrictMode 下 useEffect 会执行两次（开发模式）——定时器等副作用要可重复/有清理
