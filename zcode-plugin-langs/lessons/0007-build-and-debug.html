第 7 课：构建与调试——两条开发回路

目标：学完这课，你能独立跑起开发环境并定位问题： 知道什么时候用浏览器调试、什么时候用 runIde 真机、遇到卡死从哪查起。

一、两条开发回路（先建立全局图）

回路怎么跑适合调试什么限制
前端 dev servercd webview && npm run dev（localhost:5173）组件、样式、状态、交互（浏览器 F12 随便用）没有真 Java 桥，走 mock
真机 runIde./gradlew :intellij-plugin:runIde（启动沙箱 IDE）IPC 桥、协议通信、EDT、真实 app-serverJCEF 没有 DevTools，只能靠日志/诊断面板

工作习惯建议：先 dev server 把 UI 调好，再 runIde 验证两端。别在真机里调 UI——没有 DevTools 等于蒙眼。

二、前端回路：vite.config.ts 关键点

server: {
  port: 5173,
  strictPort: true,   // 端口被占就直接报错，不漂移（Java 端硬编码 5173）
  host: 'localhost',  // 只监听本地
},
  • strictPort：Java 端 JCEF 直连 5173，端口漂移会连不上——所以宁可报错不漂移
  • Java 端怎么知道连 5173？注释说"Java 端 JCEF 直连此地址"——开发模式下 runIde 的 JCEF 直接加载 http://localhost:5173（而不是打包后的 HTML），所以能热重载
  • 生产打包：npm run build:single → vite-plugin-singlefile 打成单 HTML 内嵌进插件，JCEF 加载本地文件

三、Kotlin 回路：build.gradle.kts 关键点

intellij {
    version.set("2024.1")     // SDK 版本（首次自动下载约 1.5GB）
    type.set("IC")            // Community 版
}
buildSearchableOptions { enabled = false }   // 跳过全量 UI 扫描（慢且易失败）
signPlugin { enabled = false }               // 开发期不签名
  • 修改 Kotlin 后跑 ./gradlew :intellij-plugin:runIde 会自动编译再启动沙箱 IDE
  • 首次会很慢（下 SDK），之后增量编译很快
  • Kotlin 单独编译命令：./gradlew :intellij-plugin:compileKotlin（只查编译错误不启 IDE）

四、真机调试三板斧（JCEF 没有 DevTools）

工具怎么用能查到什么
前端诊断面板bridge.ts 的 onDiagLog/getDiagLog（页面内显示）Java 推了哪些事件、批次大小（流式排查首选）
IDE 日志沙箱 IDE Help → Show Log / log.info(...) 打点Java 端处理路径、异常堆栈
app-server 抓包协议层直接看请求/响应 JSON协议字段对错（如 content vs message）

五、常见坑速查（本仓库实战踩过）

  • JCEF 无 DevTools：console.log 看不见？页面诊断面板 + IDE 日志替代
  • 5173 端口被占：vite 直接报错（strictPort）——先杀占用进程再起
  • runIde 后 build 删不掉文件：JCEF helper 进程锁了缓存文件（.bdic 被锁）。按命令行精确匹配杀沙箱的 jcef_helper.exe，别按镜像名杀（会误伤正式 IDE）
  • 流式不更新：先看诊断面板有没有 streamBatch；有 → 前端合并逻辑问题；没有 → Java 缓冲/推送问题（第 2 课三层节流）
  • 协议超时全挂：检查 app-server 子进程 stderr 是否被管道阻塞（4KB 管道满 → 进程假死）——这是本项目踩过的最隐蔽的坑
  • 前端改动不生效：组件忘了 import 自己的 less 文件（vite 只打包被 import 的样式）
