第 4 课：TS 基础 + React 组件——精读两个真实小组件

目标：学完这课，你能独立读懂 webview/src/components/ 下任意一个小组件 （FileRef 38 行、WaitingIndicator 54 行），明白 props、事件、状态与渲染的关系。

一、TS 五分钟：类型是你的朋友

TypeScript = JavaScript + 类型标注，编译期检查，运行时无额外开销。 本仓库最常见的三个写法（都能在 FileRef.tsx / App.tsx 里找到）：

TS 写法含义仓库实例
interface Props { path: string; onRemove: () => void }给组件的"参数表"定义类型FileRef.tsx L10-13
import type { JavaRequest } from '@/types/messages'类型专用导入（编译后消失）bridge.ts L17
const x = a ?? b空值合并：a 为 null/undefined 时取 b（与 Kotlin ?: 同义）WaitingIndicator.tsx L33

和 Kotlin 的可空性对比：TS 的空值是 null / undefined 两个（宽松）， Kotlin 只有一个 null（严格）。TS 的可空不是默认开启的（取决于 strict 配置， 本仓库 tsconfig 开了 strict，所以 props.since 可能是 undefined 时 必须用 since ? ... : '' 处理——见 WaitingIndicator L43）。

二、组件 = 函数 + props（FileRef.tsx 全文精读）

interface Props {
  path: string
  onRemove: () => void
}

/** 从路径提取文件名 */
function basename(path: string): string {
  const parts = path.replace(/\\/g, '/').split('/')
  return parts[parts.length - 1] || path
}

function FileRefInner({ path, onRemove }: Props) {     ← 解构 props
  return (
    <span className="file-ref" title={path}>
      <span className="codicon codicon-file file-ref__icon" />
      <span className="file-ref__name">{basename(path)}</span>
      <button className="file-ref__remove" onClick={onRemove} type="button">
        ✕
      </button>
    </span>
  )
}

export const FileRef = memo(FileRefInner)

五个必懂点：

  • props 是"参数表"：父组件传什么、怎么用，全在 interface Props 里声明——这就是 TS 给 React 的最大价值：传错字段编译期就报错
  • JSX 语法：标签里用 {表达式} 插值（如 {basename(path)}）， className 替代 HTML 的 class，事件用驼峰 onClick
  • 事件向上传：onRemove 是父组件给的函数，子组件只负责"点按钮时调用它"——数据流永远是"上"的
  • memo：props 没变就不重渲染（性能优化，文件引用列表会频繁重渲染）
  • replace(/\\/g, '/')：把 Windows 路径反斜杠转成 / 再按 / 分割取最后一段（跨平台文件名提取）

三、useState / useEffect 最小模型（WaitingIndicator.tsx 精读）

export function WaitingIndicator({ since }: Props) {
  const currentModel = useStore((s) => s.currentModel)      ← 读全局状态（第 5 课）
  const messages = useStore((s) => s.messages)
  const [, force] = useState(0)                             ← 用 state 计数做"强制重渲染"

  useEffect(() => {
    const timer = setInterval(() => force((n) => n + 1), 500)  ← 每 500ms 重渲染一次
    return () => clearInterval(timer)                        ← 清理函数：卸载时清定时器
  }, [])                                                     ← 空依赖：只在挂载时执行一次

  const modelName = currentModel?.modelId
    ?? (() => { /* 从最后一条 assistant 消息回退找模型名 */ })()

  const dots = '.'.repeat(Math.floor(Date.now() / 500) % 3 + 1)  ← 时间驱动的省略号
  const elapsed = since ? elapsedDesc(since) : ''

  return (
    <div className="waiting">
      <div className="waiting__spinner" />
      <span className="waiting__text">
        {modelName ? `${modelName} 正在生成响应` : '正在生成响应'}{dots}
      </span>
      {elapsed && <span className="waiting__time">（已 {elapsed}）</span>}
    </div>
  )
}

核心心智模型：

  • 渲染 = 状态的函数：组件就是"给状态，返回界面"。状态一变，React 重新执行函数体
  • useState：声明一份局部状态。const [, force] = useState(0) 只取 setter 不取值——常见的"强制刷新"技巧
  • useEffect：副作用（定时器、网络、订阅）的家。返回的清理函数在卸载/依赖变化时执行——忘写清理函数 = 定时器泄漏（评审点）
  • 依赖数组 []：只在挂载后执行一次；写 [since] 则 since 变化时重跑
  • 时间用绝对差（elapsedDesc(since)）：跨视图切换回来计时不重置——注释里特别说明了设计意图

四、组件树与单向数据流（App.tsx 视角）

App.tsx 是根组件，它：

  • 用 useState<View>('chat') 管视图切换（chat/history/settings）
  • 把 store 里的状态通过 props 往下传：<ChatView messages={messages} ... />、<InputBox onSend={(text) => sendMessage(text)} />
  • 子组件想改状态，调用父级传下来的回调（onSend/onDelete/onSelect）——回调内部再调 store 的 action

所以数据流只有一条路：状态(store) → props → 组件渲染；事件 → 回调 → action → 状态。 看不懂某个组件时，先回答三个问题：它的 props 从哪来？它读了哪些状态？它的事件回调往哪传？
