第 3 课：IntelliJ Platform 骨架——从 plugin.xml 到右侧工具栏

目标：学完这课，你能说清三行 plugin.xml 声明如何变成 IDE 右侧的 ZCode 标签， 以及 Service 的现代注册方式。

一、plugin.xml：插件的"户口本"

IntelliJ 插件没有 main() 入口，一切靠 声明式注册：在 plugin.xml 里声明 "我有这些扩展"，平台在合适的时机实例化并调用。全文只有 27 行（ intellij-plugin/src/main/resources/META-INF/plugin.xml）：

<idea-plugin>
    <id>com.zcode.ideaplugin.zcode-assistant</id>              ← 唯一 ID
    <name>ZCode Assistant</name>
    <description>在 IDEA 里管理 ZCode 会话…</description>

    <!-- 兼容的 IDE 版本范围：2024.1+ 全支持（含 2026.x）-->
    <idea-version since-build="241" until-build="261.*"/>     ← 版本范围

    <!-- 依赖 JCEF（嵌入式 Chromium，用于渲染 React UI）-->
    <depends>com.intellij.modules.platform</depends>           ← 平台依赖

    <extensions defaultExtensionNs="com.intellij">
        <!-- 注册 ToolWindow（右侧工具栏）-->
        <toolWindow id="ZCode"
                    anchor="right"
                    factoryClass="com.zcode.ideaplugin.ui.ZCodeToolWindowFactory"
                    icon="AllIcons.Toolwindows.ToolWindowProject"
                    secondary="false"/>                          ← 三行核心声明
    </extensions>
</idea-plugin>

三处关键声明：

声明含义对应代码
<idea-version since-build="241" />兼容 2024.1+ 到 2026.1与 build.gradle.kts 的 sinceBuild/untilBuild 一致
<depends>com.intellij.modules.platform</depends>只依赖平台核心，不依赖具体 IDE 产品IC/IDEA 都能装
<toolWindow id="ZCode" anchor="right" factoryClass="..." />右侧注册一个叫 ZCode 的工具栏ZCodeToolWindowFactory 类

二、ToolWindow 生命周期：声明 → 工厂 → 面板

平台遇到 factoryClass 后：首次打开标签时调用工厂的 createToolWindowContent，把面板塞进内容管理器：

class ZCodeToolWindowFactory : ToolWindowFactory, DumbAware {
    override fun createToolWindowContent(project: Project, toolWindow: ToolWindow) {
        val panel = ZCodeToolWindowPanel(project)              ← 真正的 UI 面板
        val content = ContentFactory.getInstance()
            .createContent(panel, "", false)
        toolWindow.contentManager.addContent(content)
    }
}

要点：

  • DumbAware：告诉平台"索引还没建好也能显示我"——否则开 IDEA 时索引阶段标签会灰掉
  • 面板是懒创建的：用户没点过 ZCode 标签，工厂不会执行
  • ZCodeToolWindowPanel 内部才是 JCEF 浏览器 + React UI 的宿主（第 6 课展开）

三、Service：现代注册方式（不用写 plugin.xml）

第 1 课读过的 ZCodeServiceImpl 用 @Service(Service.Level.PROJECT) 注解 声明自己是"项目级服务"。这是现代方式：注解 + 编译期处理，替代旧式在 plugin.xml 手写 <service> 标签。获取方式：

// 接口定义（ZCodeService.kt）
interface ZCodeService {
    fun getClient(): ZCodeProtocolClient
    fun isStarted(): Boolean
    fun shutdown()
}

// 扩展函数：全工程一句拿到服务（ZCodeServiceImpl.kt L47）
fun Project.zCodeService(): ZCodeService = service<ZCodeServiceImpl>()

// 调用方（如 ToolWindowPanel 里）
val client = project.zCodeService().getClient()

Service 的三个 Level：

级别生命周期典型用途
Service.Level.APP整个 IDE 进程一个全局单例（当前未用）
Service.Level.PROJECT每个项目一个，项目关闭销毁本仓库的 ZCodeServiceImpl
Service.Level.MODULE每个模块一个少用

四、启动全景（把 1-3 课串起来）

时机发生了什么
IDE 启动平台读 plugin.xml，注册 ToolWindow 扩展（此刻不创建面板）
用户点 ZCode 标签平台调 ZCodeToolWindowFactory.createToolWindowContent
面板构造ZCodeToolWindowPanel(project)：创建 JCEF 浏览器，注入 JS 桥
首次需要客户端project.zCodeService().getClient() → 懒启动 app-server 子进程（双重检查锁，第 1 课）
项目关闭shutdown()：关闭子进程、清引用
