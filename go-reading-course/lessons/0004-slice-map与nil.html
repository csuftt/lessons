slice、map 与 nil:Go 最高频容器与共享陷阱

目标:读懂并评审 Go 项目 · 实战 = tdengine-replicator

本课赢点:你能看懂 []string / map[string][2]int64 这类类型,并作为评审者抓住 Go 对 Java 人最隐蔽的陷阱——「slice 切片共享底层数组」。

1. slice = 动态数组,语法是 []T

看 buildInsert(tdengine.go:109)的开头:

func buildInsert(batch []pendingRow, maxBytes int) []string {   // ← 参数和返回都是 slice
    var (
        out   []string
        b     strings.Builder
        cur   int
        ...
    )
    b.WriteString("INSERT INTO ")
    for _, r := range batch {                  // ← 遍历 slice
        seg := buildSegment(r)
        ...
        out = append(out, b.String())          // ← 往 slice 追加元素
    }
    return out
}
Go · slice[]string = 元素为 string 的动态数组。类似 Java 的 ArrayList<String>。中括号在前,类型在后。
Java · ListList<String> / ArrayList。

三个高频操作,看一眼就够:

  • 声明:var out []string——此时 out 是 nil(零值),长度 0。nil slice 可以直接 append(不会 panic)。
  • 追加:out = append(out, x)——注意要把 append 的结果赋回去(append 可能返回新底层数组)。这点和 Java list.add(x) 直接改原对象不同!
  • 遍历:for _, r := range batch——_ 是丢弃下标,只要值。要下标写 for i, r := range。
⚠️ Java 人必踩:append 要赋值回去 Java 里 list.add(x) 就完事了。Go 的 append(s, x) 不改原 s,而是返回新 slice——你必须 s = append(s, x)。写成 append(out, x) 不接住,等于什么都没发生。评审动作:看到裸 append(...) 没被赋值 = bug。

2. 本课核心陷阱:slice 切片「共享底层数组」

这是 Go 对 Java 人最反直觉的地方。看真实代码 data_consumer.go:176:

dataVals := append([]driver.Value(nil), row[:d]...)   // ← 为什么不直接 row[:d]?

先拆解这行。这里有两个新东西:

  • row[:d] ——「切片表达式」,取 row 的前 d 个元素,类似 Java subList(0, d)。
  • ... ——「展开」,把一个 slice 展开成 append 的多个参数(类似 Java 的可变参数 addAll)。

那为什么不直接写 dataVals := row[:d]?因为 row[:d] 不拷贝数据——它只是给底层数组开了一扇新窗户。dataVals 和 row 指向同一块内存。之后改 dataVals,会悄悄改到 row!作者为了彻底断开共享,用 append([]driver.Value(nil), row[:d]...) 强制拷贝出一份新数组。

Go · 切片共享b := a[:n] 不拷贝,b 和 a 共用底层数组。改 b 的元素 = 改 a。append 超过容量时才分配新数组。
Java · subListsubList 也共享——但 Go 这个行为覆盖所有切片操作,更普遍、更容易中招。
🔑 评审心法:slice 传出去/存起来前,想清楚是否要拷贝 当一个 slice 被切片后长期持有或跨 goroutine 传递,评审问一句:「它和原数组还共享吗?原数组会被改吗?」若是,显式拷贝:append([]T(nil), src...) 或 copy(dst, src)。本项目 data_consumer.go 这行正是防这个 bug——好代码。

另一个高频:... 展开

看 resync.go:172:

tasks = append(tasks, planTableTasks(...)...)   // ← 末尾的 ...

含义:把 planTableTasks(...) 返回的 slice 整个展开追加进 tasks。等价 Java 的 tasks.addAll(...)。没有 ... 会变成「追加一个 slice 元素」(类型不对,编译报错)。

3. map = Go 的 HashMap

map 语法 map[K]V。看三个真实用法:

// meta_consumer.go:17 —— map 字面量(键值对初始化)
var typeNames = map[int]string{
    1: "create",
    2: "alter",
    3: "drop",
}

// resync.go:302 —— make 创建空 map,准备往里填
out := make(map[string][2]int64)      // key=string, value=[2]int64(含2个int64的数组)

// main.go:108 —— 字面量直接传参
_ = json.NewEncoder(w).Encode(map[string]bool{"ok": true})
Go · mapmap[K]V。引用类型。读写:m[k] = v / v := m[k]。零值 nil。
Java · HashMapMap<K,V> / put/get。

map 取值有 Go 特有的「双值」写法,区分「值为零值」和「键不存在」:

v, ok := m["abc"]   // ok=false 表示这个 key 不存在

和第 2 课的「带标志位返回值」是同一种设计——Go 喜欢把「是否存在」做成显式的 bool,而不是抛异常或返回 null。

4. nil:不只是 null,是「零值」

Go 里每个类型都有零值(声明但没赋值时的默认值)。nil 是指针、slice、map、interface 的零值。和 Java null 的关键区别:

Go · nil 行为分类型nil slice 可以 append(自动分配);nil map 写入会 panic;nil 指针调方法/字段会 panic。
Java · null对 null 做任何操作都 NPE。Go 的 nil slice 能 append,是少数「更宽松」的点。
⚠️ 评审高发:nil map 写入 panic var m map[string]int; m["a"] = 1 —— panic(assignment to entry in nil map)。必须先 m = make(map[string]int)。评审时看到 var m map[...] 后直接写,确认中间有没有 make。

5. 自测

检索练习
append(out, x) 和 out = append(out, x),哪个是对的?为什么 Go 要这么设计?
点开看答案

后者对。append 返回新 slice 而非原地修改(因为底层数组可能不够大、要重新分配)。评审规则:append 的结果必须被赋值。

评审练习
某函数返回 return row[:d](一个切片),调用方拿到后长期持有并修改。评审意见?
点开看答案

风险:返回的切片和原 row 共享底层数组。调用方修改会污染原数据。建议改成返回拷贝:return append([]driver.Value(nil), row[:d]...)。本项目 data_consumer.go:176 正是这么做的。

辨析题
var s []int 之后 s = append(s, 1),会 panic 吗?var m map[int]int 后 m[1] = 1 呢?
点开看答案

第一个不会 panic——nil slice 可以 append。第二个会 panic——nil map 写入是运行时错误,必须先 m = make(map[int]int)。口诀:「nil slice 能 append,nil map 不能写」。
