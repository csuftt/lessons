评审清单(按优先级,tdengine-replicator 实评)

A. 并发(头号雷区)

  • A1. 每个 go f(ctx) 都能通过 ctx 退出? 本项目:好 data_consumer/recovery/probeLoop 全部接收 ctx 并在循环里 case <-ctx.Done(): return。无泄漏。
    依据:data_consumer.go:110 / recovery.go:124 / 171 / 211
  • A2. WaitGroup 的 Add 与 defer Done 严格配对? 本项目:好 sc.Register() 后紧跟 defer sc.Done(),所有 return 路径都执行 Done。
    依据:data_consumer.go:30-31
  • A3. 共享状态有 Mutex 保护?锁的每条 return 都解锁? 本项目:可改进 RecoveryCoordinator 的 inflight/lastRun 有 Mutex——正确。但 Trigger 内多次手动 r.mu.Unlock()(提前 return),虽每条都对了,但易漏;建议用 defer 缩小持锁或重构临界区。可提改进项。
    依据:recovery.go:44-68
  • A4. channel 的 close 责任唯一? 本项目:好 Shutdown 中 done 只由唯一 goroutine close,接收方只读。
    依据:graceful_shutdown.go:47-51

B. 错误处理

  • B1. 每个返回的 err 都被检查? 本项目:好 openConn/queryMaxTS/consumer 创建等关键路径都检查 err。
    少数故意忽略处用 _, _ =(如 consumer.Commit)标注了「忽略」意图,可接受。
  • B2. log.Fatalf 只用于启动期? 本项目:边界 openConn 用 Fatalf——它只在 main 启动序列调用(localInit、消费者内连接也调 openConn,但那是 goroutine 里,Fatalf 会退出整个进程)。消费者 goroutine 里连接失败用 Fatalf 会打死进程,建议改 log+重连。可提改进。
    依据:tdengine.go:17 / data_consumer.go:32
  • B3. 错误判断靠字符串匹配?升级会脆裂? 本项目:风险 isIdempotentErr/isNotExistErr 用 strings.Contains(err.Error(), "not exist"),大小写还写了两个变体(作者已被坑过)。TDengine 改文案会静默失效 → 幂等误判/补偿漏触发。最值得提的设计风险。缓解:固化驱动版本(项目已锁 v3.5.5)。
    依据:tdengine.go:32-48
  • B4. 配置解析失败静默回退? 本项目:风险 envIntOr/envBoolOr 解析失败默默用默认值。端口写成 "abc" → 静默连默认端口,排查极痛。建议启动期配置失败 fail fast(log.Fatalf)。
    依据:config.go:104-122

C. 资源与 defer

  • C1. Open/Query 后紧跟 defer Close? 本项目:好 queryChildTag/queryMaxTS 在 if err==nil 之后 defer Close,顺序正确。
    依据:tdengine.go:58 / 76
  • C2. context.WithTimeout 配 defer cancel? 本项目:好 recovery.recover 正确配对。go vet 可通过。
    依据:recovery.go:77-78
  • C3. 每个 consumer goroutine 独占连接并 defer Close? 本项目:好 runDataConsumer 开 local/peer/consumer 三连接,全部 defer Close,goroutine 退出即释放。
    依据:data_consumer.go:32-53

D. 类型与数据

  • D1. 修改状态的方法用指针接收者? 本项目:好 Coordinator/metrics 全用 (x *T);TopicSpec 纯计算用值接收者,一致。
    依据:见第 3 课
  • D2. slice 切片长期持有/跨 goroutine 是否拷贝防别名? 本项目:好 parseRow 用 append([]driver.Value(nil), row[:d]...) 显式拷贝 dataVals,防止共享原行底层数组。
    依据:data_consumer.go:178 / 见第 4 课
  • D3. nil map 写入?nil slice 追加? 本项目:好 map 都用 make 初始化;slice 用 append 赋值回。
    依据:resync.go:302 等
  • D4. 类型断言用双值形式防 panic? 本项目:好 parseRow 的 .(bool)/.(string) 都用 , ok 安全形式。
    依据:data_consumer.go:170-173 / 见第 5 课

E. 设计与地道性

  • E1. 接口小而聚焦?无接口污染? 本项目:好 几乎不定义自定义接口,直接用 driver-go 具体类型 + 内置 error。地道。
  • E2. 依赖少且精确锁版? 本项目:好 仅 2 个直接依赖,版本固定(尤其 driver-go native 固化 v3.5.5,注释说明原因)。
  • E3. 并发安全有测试覆盖? 本项目:可改进 仅 parse_test.go 一个测试。resync/recovery 等核心并发逻辑缺测试。建议补 runResync diff 逻辑的单测 + go test -race。
    依据:parse_test.go 是唯一测试

把清单变成你的肌肉记忆

评审任意 Go PR 时,按 A→B→C→D→E 顺序扫一遍。其中 A(并发)和 B(错误)出 bug 概率最高、最致命,优先看。这张表是「最小可用集」,随你经验增长可以扩充。

综合演练
拿本项目任意一个文件(如 meta_consumer.go / resync.go),照清单 A→E 扫一遍,看能不能找出上面没列到的一个点。
