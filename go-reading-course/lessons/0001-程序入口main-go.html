从 main.go 入手:Go 程序的入口与启动流程

目标:读懂并评审 Go 项目 · 实战 = tdengine-replicator

本课的赢点:读完这一课,你能用一句话说清 tdengine-replicator 启动时按什么顺序做了什么。这是读懂任何 Go 项目的第一站——找到入口,顺着它往下读。

1. 找入口:永远是 main.go 里的 func main()

Java 的入口是 public static void main(String[] args)。Go 的入口更朴素:

// 文件:main.go(项目根目录)
package main          // ① 声明这是「可执行程序」的包

import (              // ② 导入依赖,类似 Java 的 import
    "encoding/json"
    "log"
    "net/http"
    "os"
)

func main() {         // ③ 入口。无参数、无返回值。
    cfg := loadConfig()
    ...
}

三件事就够你起步:

  • package main —— 告诉 Go「这是个可执行程序,不是库」。库会是 package tdengine 这种。
  • func main() —— 程序入口。整个项目只能有一个 package main 的 main 函数。找到它,就找到了程序的总指挥。
  • import (...) —— 用到的标准库/第三方包。"log"、"os" 是 Go 标准库,类似 JDK 自带。
Gofunc main()
无参无返回,命令行参数用 os.Args 取。
Javapublic static void main(String[] args)
参数在签名里。

2. 顺着 main() 往下读:启动顺序就是执行顺序

Go 没有 Spring 那种「依赖注入 + 注解扫描」的魔法。main() 里的代码从上到下就是执行顺序,这反而比 Java 好读。看真实代码(精简版):

func main() {
    cfg := loadConfig()                          // 1. 读配置(全环境变量)

    cfg.DataTopics, cfg.MetaTopics, perr =       // 2. 从 init.sql 解析 topic
        parseStables(initSQLText)

    sc := newShutdownCoordinator()               // 3. 建关闭协调器
    ctx := sc.ctx

    m := newMetrics(cfg)
    go m.pushLoop(ctx)                           // 4. 启动指标推送(goroutine)

    recovery := newRecovery(cfg, m, initSQLText)
    go recovery.probeLoop(ctx)                   // 5. 启动重建探测(goroutine)

    localInit := openConn(...)                   // 6. 初始化本机 schema
    initSchema(localInit, cfg, initSQLText)
    localInit.Close()

    startDataConsumers(ctx, cfg, ...)            // 7. 启动数据面消费者
    startMetaConsumers(ctx, cfg, ...)            //    启动 META 面消费者

    go maybeResync(ctx, cfg, m)                  // 8. 重建回补
    go runHTTP(cfg, m, recovery)                 // 9. HTTP 服务

    sc.waitForShutdown(10 * time.Second)         // 10. 阻塞等关闭信号
}
🔑 读懂 Go 的第一个心法 看 main() 的顺序 = 理解程序的骨架。你已经能看出:这个进程启动后并行跑了好几个后台任务(指标推送、重建探测、HTTP 服务),主线程最后卡在 waitForShutdown 等信号。这就是整个进程的运行模型。

两个新语法,看一眼就够

Go · :=cfg := loadConfig()
「短声明」:声明变量并推断类型。Java 10 的 var。函数内到处都是它。
Javavar cfg = loadConfig();
Go · go f()go m.pushLoop(ctx)
「goroutine」:在新的轻量线程里跑这个函数,不阻塞当前线程。相当于 Java 开个线程异步执行。
Javanew Thread(() -> pushLoop(ctx)).start();
或 Java 21 虚拟线程。

现在你能翻译第 4、5、8、9 行了:「go xxx(ctx)」= 「起个后台线程跑 xxx」。它们和主线程并发执行。

3. 评审视角:看 main 要问的三个问题

作为架构师,你评审 Java 的启动类会问什么?Go 一模一样:

  1. 初始化顺序对不对? 这里 ctx 在第 3 步创建,之后所有后台任务都用它——顺序正确。若某个 go 用了还没初始化的东西,就是 bug。
  2. 后台任务有没有泄漏? 每个 go f(ctx) 都要能通过 ctx 被取消而退出。第 7 课我们会专门评审 goroutine 泄漏——这是 Go 评审的第一大雷区。
  3. 谁阻塞主线程? waitForShutdown 没有它,main 返回 → 进程立即退出,后台任务全死。评审时确认它存在。

4. 自测:用一句话描述启动流程

检索练习 · Retrieval
不看上面代码,回忆:main() 最后那行 sc.waitForShutdown(...) 如果删掉,会发生什么?
点开看答案

main() 会立刻返回 → 整个进程退出 → 之前用 go 启动的所有后台任务(指标推送、消费者、HTTP)被强制终止。所以这行是「让主线程活着、等关闭信号」的锚。Java 里你通常靠阻塞队列或 server.await() 达到同样效果。

翻译练习 · Java→Go
go m.pushLoop(ctx) 这一行,用 Java 写最接近的等价是?
点开看答案

异步启动一个后台任务执行 pushLoop。最接近:new Thread(() -> m.pushLoop(ctx)).start();(或用 Executor 提交)。关键理解:go 之后当前函数不等待,立刻继续往下执行。
