第 8 课：错误码与避坑清单

最后一课不学新东西，把前 7 课的教训浓缩成一页防呆手册： 一张错误码表、十条避坑军规、一份"此路不通"负面结论清单。出问题时按图索骥。

一、错误码速查表

code含义标准处置
-32600帧格式非法（典型：带了 jsonrpc 字段）检查信封
-32601方法不存在 / 未注册 handler查方法名拼写；反向请求未实现要主动回它；v2 删掉的老方法（upsertModelProvider）也报这个
-32602参数非法（v2 strict：Unrecognized key）双代形状自适应降级重发（被拒不生效，重发无副作用）
-32603内部错误（语义五花八门）看 message：渠道不在注册表 / 退订缺三件套 / setModel 与并发校验竞态…
-32004会话未激活（close/read 等撞冷会话）先 resume；槽位满（16 LRU）才考虑挤槽
-32031restoreWarning：会话缺模型上下文，send 被拒send 带上当前模型原路重试
stale（业务态）CAS 基准过期用 revisionAtDecision 重试（fork/edit/deleteQueueItem）
超时的两种面孔 全量超时（所有请求都超时）= 进程级卡死：先查 stderr 排空、reader 线程死没死； 单会话超时（其他会话正常）= resume 中断回合后的"忙窗口"（1.5~2 分钟指数退避），延迟重试即可，别判死。

二、十条避坑军规

  • 1. stderr 永远排空——4KB 管道堵死=全线超时（第 1 课）；
  • 2. 单帧失败不外溢——读循环 try-catch 兜底丢帧，形状不可控字段一律安全转换（遥测数组帧杀 reader 实踩）；
  • 3. 先 subscribe 再 send，白名单先登记再发订阅请求（首帧不等 ack）（第 3 课）；
  • 4. 写操作禁重试，只有幂等读允许超时重试（send 重发=两条消息）（第 1 课）；
  • 5. 冷会话先 resume，-32004 先想冷会话再想槽位满（第 2 课）；
  • 6. stop 走 v4，流式期停后自己合成收尾帧；后台任务用 cancelBackgroundTask 单独停（第 4 课）；
  • 7. -32602 是 strict 拒绝的唯一可靠信号，按双代形状降级重发（第 5 课）；
  • 8. 思考级别候选值只认服务端 available，setModel → read → setThoughtLevel 严格串行（第 5 课）；
  • 9. 反向请求必应答：未知方法回 -32601，无人值守回 decline，handler 异步（第 6 课）；
  • 10. v4 写命令走 CAS 三步舞：首发 0 必 stale，revisionAtDecision 重试（第 7 课）。

三、负面结论清单：此路不通，别再试了

这些都是实测过的死路（探索成本很高，务必记住）：

想做的事为什么不行替代方案
legacy session/stop 停回合新版 CLI 处理器未接新原语，发了没反应v4/command stop
对子会话用 legacy subscribe 收事件订阅成功但恒 0 投递v4/conversation/subscribe
RPC 注册渠道图持久（upsert 等）纯运行时态，重启即丢；v2 已删除该方法写 config.json / provider_config.json
guide 插队带附件服务端强制降级 queue（attachmentsUnsupported）UI 预拦截或降级提示
闲时（off-peak）任务的 CRUD定义在官方 Electron 宿主私有存储，无 RPC自建调度器（automation/* 只管 Cron 任务）
不注凭证 env 裸启动create 报 Model config is missing；注入不能取消启动时注入三件套
legacy fork 通道行为怪（事件乱序、无 target 全量 fork 报错）、已弃用v4 forkAssistant + CAS
goal 的 tokenBudget 设置没有设置入口，只能读UI 只读展示
信 --version 判 CLI 代际版本号长期不 bump读 zcode.cjs 找标记串

四、诊断三板斧（排查协议问题的顺序）

  • 录帧：宿主侧把 stdin/stdout 全量落盘（行式 JSON），一切争议以帧为准；
  • 最小复现：用 20 行 Python 骨架（第 1 课）剥离宿主复杂度，单帧复现；
  • 对表：错误码表 → 军规 → 负面结论，80% 的问题能在表里直接命中。
