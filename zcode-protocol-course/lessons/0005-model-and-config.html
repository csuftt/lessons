第 5 课：模型与配置

目标：掌握模型六方法，重点搞定双代参数差异与 strict schema 自适应降级。 这一课的方法最容易被 CLI 升级打断，所以"怎么防"比"怎么调"更重要。

一、模型方法全景

方法作用会话级?
session/setModel切换会话模型是
session/setThoughtLevel切思考级别（off/high/max…）是
session/updateRuntimeModelConfig推完整运行时模型配置是
workspace/generateText一次性生成（标题、润色）不带会话否
workspace/upsertModelProvider注册自定义渠道（v2 已删）否
workspace/updateProviderRegistry推渠道注册表（运行时态）否

二、session/setModel：同一方法，两代形状

// v1 代（宽松）：带完整 runtimeModel 大对象
{"id": 30, "method": "session/setModel",
 "params": {"sessionId": "sess_abc",
            "model": {"modelId": "glm-4.7", "providerId": "bigmodel-api"},
            "runtimeModel": {"revision": "0", "generatedAt": 1758000000000,
                             "model": {"providerId": "bigmodel-api", "modelId": "glm-4.7"},
                             "provider": {"providerId": "bigmodel-api", "kind": "...",
                                          "label": "...", "source": "...",
                                          "baseURL": "https://api.z.ai/api/anthropic",
                                          "apiKey": {"source": "inline", "value": "..."},
                                          "models": [{"modelId": "glm-4.7", "contextWindow": 200000,
                                                      "maxOutputTokens": 32768, "supportsImages": true,
                                                      "supportsPdf": true, "supportsVideo": false,
                                                      "label": "GLM-4.7"}]}}}}

// v2 代（strict）：纯模型引用，options.reasoningLevel 对有 reasoning 的模型必填
{"id": 31, "method": "session/setModel",
 "params": {"sessionId": "sess_abc",
            "model": {"providerId": "bigmodel-api", "modelId": "glm-4.7",
                      "options": {"reasoningLevel": "high"}}}}
strict schema：多一个字段就拒收 v2 代用严格校验，params 里出现它不认识的 key（比如按 v1 习惯多塞的 runtimeModel）直接 -32602 "(root): Unrecognized key"。好消息是：参数被拒时切换并未生效， 所以"被 -32602 拒 → 换参数形状重发"没有副作用。插件的自适应策略： 先按新代形状发，收到 -32602 就降级旧形状重试，反之亦然（三态探测，实际只探测一次就记住本代）。

切模型的回执与状态对账也有一套：切换成功后靠 session.updated（model 字段）+ state.updated 对账； CLI 的模型管理接口有 TTL，回执迟到时宿主重发会撞出"幽灵横幅"——用 ack 会话集合去重。

三、setThoughtLevel：候选值永远是服务端权威

{"id": 32, "method": "session/setThoughtLevel",
 "params": {"sessionId": "sess_abc", "thoughtLevel": "high"}}
// 发之前：session/read → settings.thoughtLevel.available 里查这个模型认哪些值

两个坑：① 级别集因模型而异（GLM=off/high/max，qwen=enabled/disabled），硬编码必翻车； ② 校验按"当前生效模型"进行——createSession 后立刻并发 setModel + setThoughtLevel 是竞态， 级别按旧模型校验直接 -32603。顺序必须串行：先 setModel，read 拿新 available，再 setThoughtLevel。

四、workspace/generateText：不带会话的快速通道

标题生成、输入润色这类"问一句拿一段文字"的需求别建会话，直接：

// v2 形状（selection + maxOutputTokens 必填）
{"id": 33, "method": "workspace/generateText",
 "params": {"workspace": {"workspacePath": "G:\\demo"},
            "selection": {"providerId": "bigmodel-api", "modelId": "glm-4.7",
                          "options": {"reasoningLevel": "high"}},
            "maxOutputTokens": 256,
            "prompt": "给这个对话起个 8 字以内标题：...",
            "querySource": "title_generation"}}
// → {"id": 33, "result": {"text": "重构协议客户端", "finishReason": "stop", "usage": {...}}}
// v1 形状：selection 换成 modelRef，去掉 maxOutputTokens；messages:[{role,content}] 形态也支持

注意：generateText 的模型选取规则与会话模型可能分叉（各自有默认值链）， 自定义渠道下它可能 -32603 渠道错位——兜底方案是退回 CLI 一次性子进程（zcode -p）跑同任务。 另外它默认走注册表找渠道，新注册的渠道要在调用前注册好（upsertModelProvider 或写配置文件），未注册会报 -32603，此时可先 upsert 自愈再重发。

五、渠道持久化：RPC 写的都是运行时态

跨重启必丢 upsertModelProvider / updateProviderRegistry（v1）写的是进程内注册表，不落盘。 自定义渠道要持久，唯一途径是写配置文件：v1 写 ~/.zcode/cli/config.json 的 provider 注册表， v2 写 ~/.zcode/v2/provider_config.json（服务端 watch 热加载，约 2 秒内生效）。 两套命名还不一样（文件端 name/options.apiKey/limit.context vs RPC 端 label/apiKey/contextWindow），别照抄字段名。

内置渠道列表怎么拿？插件实际用的是读文件 + 读会话设置双源合并，而不是某个 RPC—— "列出可用模型"没有专门的 RPC 方法，模型列表 = 配置文件里的渠道定义 ∪ 会话 read 出的当前模型。
